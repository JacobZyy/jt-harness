1

血缘判定：它到底是不是"二开"

"二开"通常意味着在原代码基础上改。我们用四条独立证据检验这个假设。

证据一：GitHub API 显示非 forkGitHub 官方接口返回 fork: false、无 parent/source 仓库。rex 版 2026-03-01 独立建仓，与原版（2024-01 建仓）在 GitHub 的仓库谱系上没有任何派生关系。
证据二：技术栈零重叠原版是 Python（FastAPI 内核 + Cerebrum SDK），rex 版是 Node.js 24 纯 ESM + TypeScript。两边连一个可以对应的源码文件、一个同名函数都找不到。
证据三：rex 版从未提及原版对 rex 版全库（含 15 万行代码与全部文档）检索 agiresearch / rutgers / cerebrum / 论文 arXiv:2403.16971——零命中。README 没有致谢，CHANGELOG 没有溯源。
证据四：出生时的形态完全无关rex 版的第一个提交（2026-03-01）是"小红书运营助手核心技能和反检测功能"——它最初是一组个人技能脚本，后来才长成本地 Agent 工具箱。原版则是实验室论文工程。
结论：不是代码层面的"二开"，而是"同名同命题的独立重建" 两者的共同点只有一层：同一个名字（AIOS）和同一句命题——"AI Agent 需要一个操作系统"。 rex 版借用了这个概念旗帜，但内核、代码、架构全部是自己另起的。不过有趣的是，rex 版内部文档显示它把原版 AIOS 生态里的核心组件（mem0、Zep——正是原版的两大记忆 Provider）当作竞品在持续跟踪研究（详见第五章）。所以更准确的画像是：它没有 fork 原版的代码，但站在了原版参与开创的"Agent OS"赛道上，并把原版的生态伙伴当成了对标对象。
一个 license 上的小细节 原版仓库根目录的 LICENSE 文件是空的（1 字节，无任何许可证文本，GitHub 页面因此不显示 license 类型），只有 Rust 子目录声明了 Apache-2.0；rex 版则是标准 MIT（Copyright 2026 Rex）。也就是说即使真有人想基于原版做代码二开，原版目前也没有给出法律许可——好在两边本来就无代码继承。

原版 AIOS 是什么：学术界的 Agent 操作系统

rutgers agiresearch 实验室的论文工程，6.3k stars，COLM 2025。

原版 AIOS 的自我定位（README 原话）：把 LLM 嵌入操作系统，为 LLM Agent 的开发部署解决调度、上下文切换、内存管理、存储管理、工具管理等问题。它分两部分：AIOS Kernel（本仓库，资源管理内核）+ Cerebrum SDK（独立仓库，Agent 与内核交互的客户端）。整篇论文谱系很完整：AIOS 主论文（COLM 2025）、LSFS 语义文件系统（ICLR 2025）、A-MEM 记忆（arXiv:2502.12110）、Cerebrum SDK（NAACL 2025）。

2.1 它的运行方式：一台"真·操作系统"样子的服务器

Agent（经 Cerebrum SDK / HTTP）
↓ POST /query
FastAPI 内核（launch.py，uvicorn 常驻 8000 端口）
↓ 包装成系统调用
SyscallExecutor → 四条全局队列（LLM / Memory / Storage / Tool）
↓ 阻塞式 syscall，线程 join 等结果
调度器：FIFO（按 1 秒窗口攒批）或 RR（时间片 + 上下文切换）
↓
资源管理器：LLMAdapter（多后端/智能路由）· MemoryManager · StorageManager(LSFS) · ToolManager(MCP/沙箱)

几个有辨识度的设计：

  • 系统调用模型：Agent 的每次资源请求都被包装成 LLMSyscall / MemorySyscall / StorageSyscall / ToolSyscall，压入全局队列由调度线程消费——Agent 线程阻塞等待，完全复刻"进程发起 syscall"的语义。Agent 由 AgentFactory 加载（本地包或从 Agent Hub 下载），进程表用 proc/*.json 文件模拟。
  • 两种调度器：FIFO 按 batch_interval（默认 1 秒）攒一批 LLM 请求，按模型分组、双层线程池并行；RR 给每个请求 1 秒时间片，时间片耗尽时由 Context Manager 中断生成、保存 KV-cache（本地 HF 模型可保存 past_key_values 精确恢复），下轮续跑——这是"LLM 时代的进程上下文切换"的直接实现。
  • SmartRouting 智能路由：用向量库存历史 query、LiteLLM 实时取 token 价格，做"性价比感知"的模型选型。
  • LSFS 语义文件系统：在真实文件之上叠 ChromaDB 向量索引（llama_index 摄取）+ Redis 版本链（watchdog 监听文件变更，最多 20 个版本）支持 sto_rollback 语义回滚。
  • 工具沙箱：FastMCP 的 linux-mcp 子进程 + OSWorld 的 DesktopEnv 虚拟机沙箱（docker/aws/azure/gcp 等 provider）做 computer-use。
  • 部署模式：本机内核（Mode 1）或远程内核（Mode 2），Roadmap 还有"账号化个人内核同步、内核虚拟化"（Mode 2.5~4），是奔着"Agent 时代的云操作系统"去的。

2.2 它当前的开发重心：跨 Agent 共享记忆

原版最近的提交几乎全部集中在 memory 子系统（2026 年 6-7 月："isolate mem0 collections by user"、"enforce user isolation during context injection" 等大量隔离修复）。docs/SHARED_MEMORY_SYSTEM.md（471 行）定义了完整的多 Agent 围绕同一人类用户协作写记忆的规范：memory_type（profile/task_context/conversation）× sharing_policy（shared/private）两种元数据，user_id 是主隔离边界，三层防御（物理 per-user collection → 向量库 WHERE 硬过滤 → 注入器 fail-closed 过滤），外加 MemoryWriteBarrier 强制"先写后读"顺序。记忆单元是 A-MEM 论文的 MemoryNote（content/keywords/links/evolution_history…），注入方式是 ContextInjector 在每次 LLM 调用前把检索到的记忆拼进 system message——典型注入式。Provider 可插拔：in-house（ChromaDB/Qdrant）、mem0（Mem0+Ollama embedding）、zep（Zep Cloud 图谱 API）。

给原版画个像 这是一个研究内核：奔着论文和操作系统语义去的，资源调度、上下文切换、语义文件系统、多 Agent 共享记忆是它的四张王牌；代价是工程形态重——Python 常驻服务、Redis/ChromaDB 等一堆外部依赖、Agent 要通过 SDK 走 HTTP 才能用上它。仓库里还留着 [MEM0_DEBUG] 调试日志和写入 /tmp 的调试代码，能看出功能仍在密集打磨。

记忆系统对撞（重点）

两边都自认解决"Agent 失忆"，但方向几乎完全相反。

4.1 五个正面对撞点

对撞点原版rex 版
注入 vs 拉取 注入式：ContextInjector 在每次 LLM 调用前自动检索、把相关记忆拼进 system message（受 relevance 阈值、token budget 多级过滤） 拉取式：明确禁止注入会话历史（AGENTS.md 原话），Agent 按需 search/recall，钩子注入也限死 6 条/2000 字符预算
向量 vs 词法 全线 embedding：ChromaDB/Qdrant 向量库、sentence-transformers 本地模型、Mem0 的 nomic-embed、Zep 图谱检索 零向量：ICU 中文分词 + CJK bigram + 关键词打分；源码注释明说"语义判断是 LLM 的工作"，预留 sqlite-vec 但未实现
记忆单元 MemoryNote（A-MEM 论文：keywords/links/evolution_history，记忆会"进化"） memo 事件（schemaVersion/eventId/supersedes/validAt/refs）+ 会话三层流水（L0/L1/L2）
共享 vs 单人 核心命题之一：多 Agent 围绕同一 user 协作，per-user 物理隔离 + 共享矩阵 + 写屏障（当前密集开发） 单机单人优先；只有 project_shared / agent_private 两档 scope，agent_private 30 天 TTL——用最轻的方式处理了隔离
记忆质量闭环 靠检索阈值与记忆进化（A-MEM 的 links/evolution） 独有的声明式反馈：AI 必须声明哪条记忆真的被用了（<!--memory: useful=...-->），被证实的才加权——用不到的记忆不会被抬高

4.2 有趣的收敛进化

尽管方向相反，两套系统在两个点上独立演化出了同样的答案，这说明这些设计可能是该问题的"正确解"：

收敛点一：隔离边界

  • 原版：user_id 是主隔离边界，private 记忆跨用户不可见，三层防御 fail-closed
  • rex 版：scope（共享/私有）+ agent 身份校验，private 记忆跨客户端不可见
  • 启示："记忆必须有归属和可见性边界"是两边各自得出的同一结论

收敛点二：事实失效而非删除

  • 原版 provider 生态：Zep 图谱的 valid_at / invalid_at 四时间戳机制
  • rex 版：memo 的 supersedes 链——旧记忆被新结论替代时标记失效而非物理删除，且永久保留追溯链
  • 启示："记忆是时序证据，不是可覆盖的变量"

rex 版记忆设计的真实灵感来源

"二开对象"找错了人？rex 版自己的文档给出了真正的参考系。

前一章我们确认 rex 版从未提及原版 AIOS。但它内部有一套完整的竞品研究体系：docs/reports/competitor-watchlist.json（schema v3 权威清单）+ 三份深度分析文档，还把竞品仓库克隆到 temp/competitor-repos/ 做源码级分析，然后列出"可借鉴思路"、排期实现、在 roadmap 里打勾。把 2026-05-22 那份《竞品库：Agent Memory 系统》的借鉴清单，和 rex 版今天已实现的特性放在一起，对应关系几乎是逐条兑现：

这一章修正了"二开"的真正含义 rex 版没有二开原版 AIOS 的代码，但它做了一件工程上更严格的事：把整个"Agent 记忆"赛道（TencentDB、mem0、Zep、Letta）当参考系，逐家提取可验证的核心主张，再以"本地优先、零向量依赖、文件可读"为约束条件重新实现了一遍——并在 roadmap 文档里留下完整的"主张 → 借鉴 → 实现"审计链。顺带一提：mem0 和 Zep 恰好是原版 AIOS 的两大记忆 Provider，所以 rex 版通过竞品研究，实际上间接对标了原版 AIOS 的生态组件——这大概是两个"AIOS"之间唯一一条真实的暗线。
也有"不借"的部分，而且是有意为之 竞品四家全部押注向量检索（SQLite+sqlite-vec、Qdrant、Neo4j、pgvector），rex 版至今坚持零 embedding。这不是漏了——它的对比表里明确写着各家"检索方式：BM25+向量+RRF vs 文件读取"，然后选择了用"查询降级梯子 + LLM 兜底语义判断"来补词法检索的短板，并把 sqlite-vec 列为未来意图。一份 2026-05 的文档结论可以概括它的态度："方向确认而非转向"——竞品越堆向量，它越确信自己该先把 harness 可靠性做扎实。
6

总评：同一命题的两条路线

"AI Agent 操作系统"这个 2023 年被提出的愿景，长出了两株很不一样的植物。

原版路线：OS 的"内核态"

原版把 OS 类比推向了最字面的方向：syscall、进程表、调度器、时间片、上下文切换、虚拟文件系统——它想成为 Agent 时代的 Linux 内核，让 Agent 的每一次 LLM 调用、记忆读写都经过内核的资源仲裁。这条路线的代价是"重"：常驻服务、外部依赖、SDK 客户端、多机部署 Roadmap；收益是研究价值——批处理调度、KV-cache 级上下文切换、共享记忆隔离矩阵，都是可以直接写论文的问题。

rex 版路线：OS 的"用户态"

rex 版把 OS 类比落在了最实用的方向：文件系统（.aios/ 目录）、权限纪律（rex 工单/证据门禁）、多用户隔离（scope）、软件包管理（skill 投影/init/doctor）。它没有内核、没有 syscall，反而刻意做"薄"——无常驻服务、零外部依赖、状态全是人类可读文件。它的收益是今天就能用在生产；代价是没有原版那种调度层面的研究深度（LLM 攒批、路由优化交给了 model-router 和外部客户端）。

最后回答你的原始问题："改了什么" 严格说，rex 版不是"改"出来的，而是带着同一个名字、从零重写的另一个答案。它保留了原版命题的"魂"（Agent 需要资源管理层），换掉了"形"（Python 内核 → Node 本地工具箱），并在原版完全没有的方向上做了加法（rex-harness 证据内核、隐私门、多客户端投影），在原版重仓的方向上做了减法（向量检索、多用户共享记忆、服务端部署）。如果非要用一句话定义两者的关系：原版是这篇论文的"作者"，rex 版是这篇命题最认真的"读者"之一——读完没有抄，而是交了一份方向相反、严谨程度不输的作业。
