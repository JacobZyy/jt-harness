# 记忆恢复与 Codex Goal 长任务实测

## 目标与范围

在当前 jt-harness 项目安装 Flow，用记忆异常恢复作为真实长任务，验证有序阶段、持久检查点、中断恢复和 Codex Goal 自动续轮。独立安装交付不在本次范围内；Provider、模型和生成参数保持不变，没有清空历史任务。

Flow 任务为 `d4454ab7-8e68-4bef-875d-3901781fe69b`。本轮回补对象固定为开始时的 13 个 failed 和 4 个 partial，以及修正产生的后续批次。执行期间 Hook 新接收的会话继续走正常队列，不把新增输入不断并入本轮验收目标。

## 已交付行为

- `memo retry` 从已有提炼检查点继续；原错误追加到 `jobs.failure_history`，不再因清除当前 error 而消失。
- `memo recover <id>` 展示原 issue、修正回执、后续任务和未解决数量；`memo recover <id> corrections.json` 按原路径接收显式修正或说明不采纳原因。
- 修正提炼条目另建后续批次，保留原接收时间和执行配置，跳过再次提炼。原有效正文、向量和回执保持不变。
- 修正关系复用原条目与向量，沿用事务、范围、证据和时效规则。已失效的新条目不能被旧修正重新启用。
- 原模型输出和诊断保留。相同修正幂等；冲突修正拒绝覆盖；一份修正请求中途出错会整份回滚。

恢复入口由主 Agent 或调用者核对来源后提供修正。没有另起一个修复模型，也没有将 `partial` 重新提炼成整批新数据。补录条目的旧记忆比较仍由现有 DSH 路径执行。

数据库从 v5 增量升级至 v6，增加恢复回执与错误历史。旧代码不能直接连接 v6；代码回退应同时考虑数据库版本。升级前数据库备份保存在本机 `.jth/backups/memo-before-recovery-v6-1789725382074.dump`，大小 4,596,827 字节，权限 0600。

## 阶段与 Goal 的分工

本次使用同一个原生 Codex Goal，Flow 保存四个步骤：安装与基线、实现与隔离验证、真实回补与恢复演练、最终验收与报告。

`phase` 表示讨论、执行、验收、完成；`steps` 表示具体工作阶段。步骤只能按顺序完成，必须记录结果证据；追加步骤使旧验收失效。步骤全完成仍须通过总目标验收。

原生 Goal 工具由主 Agent 调用，不由 jth 通过私有 App API 驱动。Skill 要求用户明确授权且宿主工具可用时才创建 Goal。恢复时读取 `get_goal` 与 `flow context`；阶段完成不关闭总 Goal，全部验收并 `flow finish` 后才调用 `update_goal`。

## 实测证据

| 场景 | 结果与边界 |
| --- | --- |
| 当前项目安装 | 实际执行 `flow install --project jt-harness`；Skill 链接指向本工具源文件，Flow 与 Memo Hook 保留共存。 |
| 中途追加约束 | 追加“不做独立安装交付”的测试约束后，原目标和既有验收保持不变。 |
| 暂停、恢复 | 实际使用独立 CLI 进程执行 pause 和 resume；原任务 ID、目标、完成的两步、约束均恢复，继续第三步。 |
| Hook 上下文恢复 | 通过已安装的 Hook 命令回放 Interrupt、SessionStart/compact 输入；返回原目标及第三步，上下文为 2,976 字符，没有把停止当完成。这里是事件回放，不宣称实际发生了模型上下文压缩。 |
| 原生 Goal 跨轮 | 首轮结束时 Goal 保持 active；宿主实际发送 Goal continuation，下一轮读取同一任务与步骤，继续回补而未重建或缩小目标。 |
| 发布完整性 | 中途对照基线，79 批 source/extraction 哈希和 68 个向量回执哈希均保持不变；doctor 检查 83 批材料、70 个回执，0 项错误。最终快照在回补后再次核对。 |
| 自动检查 | 类型检查、28 项离线测试、37 项 PostgreSQL 集成检查通过；当前项目也通过 `flow verify` 执行同一组检查。 |

PG 检查涵盖：修正后的条目遇到 Embedding 503 后可续跑且不再次提炼；关系恢复不调用 Embedding；相同修正并发提交只有一个回执；错误请求回滚已经执行的关系修改；v4/v5 升级不重写原数据；阶段恢复、禁止越过未完成步骤、子会话不能完成主阶段、追加步骤撤销旧验收资格。

这些证据证明本次任务中的持久状态与恢复机制生效，不证明所有模型、所有长任务均不会语义偏移。实际压缩后的模型行为还需要自然发生的长会话继续观察。

## 回补记录

首批六项诊断按来源核对后处理：两项引文在工具 JSON 中的转义形式修正；三项跨范围 supplement 记录不采纳原因，保留两端事实；一项消息 ID 多写字符，修正引用后只补录该条。后续重试还发现关系引用了同批另一条消息，已改为新记忆本来就引用的实际证据消息。

旧 failed 重试与修正条目的后续批次仍在执行，完成后更新本节统计。不会把 queued/running 当作成功，也不会将原任务的历史 partial 改写成一次无错误的运行。
