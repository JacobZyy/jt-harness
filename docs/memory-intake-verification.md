# 记忆按条目接收与原始输出留存

> 历史验证：本文记录显式 legacy 路径的模型输出接收能力；当前默认声明后台不运行 DSH 提炼或比较。现行操作见[文档导航](README.md)。

本次优化移除四项额外硬拒收行为：实体逐字匹配、每条必须引用新增消息、来源角色/确认顺序匹配，以及一个模型条目出错就拒收整批。没有移除 JSON 可读性、真实 ID、同范围引用、时效证据或数据库事务保护。

## 行为

- Agent 负责分类和语义判断，原始消息角色与顺序不改写。实体可用 `PostgreSQL` 表述来源中的 `PG`，旧上下文引用不会自动判为重复并拒收。
- 支持的条目继续入库与索引；未接收条目保存原值、位置和原因，状态为 `partial`。字段去空/去重及未知辅助字段处理不修改正文，原始完整响应单独保留。
- 比较关系按条检查，无效关系不修改旧事实，也不额外阻断已通过提炼检查的新正文；有效记忆继续可召回，关系错误单独保留。
- 模型已返回的文本在业务解析前持久化，因 token 上限停止时也保留 SDK 已返回的片段。整体 JSON 不能解析时仍可反馈修复一次，两次原文都保留。局部问题不触发整批重新生成，避免好条目被第二次回答替换。
- `partial` 与执行失败 `failed` 分开。即使零条被接受，只要存在条目诊断，也不能当作正常空记忆成功。旧失败任务可显式 retry；partial 已发布内容不被整批重试覆盖。

## 验证

`pnpm build`、`pnpm typecheck` 通过；离线测试 28 项通过，隔离 PostgreSQL 测试 35 项通过。

单元场景覆盖别名、旧上下文、角色与顺序差异、重复来源 ID、坏引用与好条目混合、非法集合、无效修订及完全无法解析的 JSON。

隔离 PostgreSQL 场景覆盖：

1. v4 升级 v5 后，原材料、条目 ID、正文哈希、向量及索引哈希保持一致。
2. 混合输出中坏引用单独保留，两个好条目可真实搜索；模拟 Embedding 503 后重试，仍使用第一次提炼，原始模型输出不重复生成。
3. 无效关系不作废旧事实，相关新端点保留，独立新事实仍可检索。
4. 两次无法解析的 JSON 都能通过 `memo outputs` 读取，不依赖 DSH Web 日志。

测试使用隔离临时数据库和模拟模型/Embedding 响应，不向正式记忆库写测试事实。原有存储事务、版本冲突、范围隔离和 Flow/PG 生命周期测试一并回归。

## 查看结果

`jth memo status --summary` 查看 complete/partial/failed 数量；`status <id>` 查看问题路径；`read --submission <id>` 查看规范结果和未接收原值；`outputs <id>` 查看提炼与比较每次返回的原文。

schema v5 只增加诊断字段、`agent_outputs` 表与 partial 状态，不改写旧内容。旧版未留存的无效响应不能逆向恢复，原会话仍保留。数据库升级需 `jth memo init`；不应直接用只认识 v4 的旧代码读取升级后的库。
