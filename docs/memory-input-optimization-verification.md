# DSH 输入优化与手动验证

> 历史验证：本文记录旧 DSH 路径的输入和缓存实验；其中 Hook 开关与运行数据只反映验证当时。现行操作见[文档导航](README.md)。

验证时间：2026-09-19 23:47，北京时间。运行标识：`2026-09-19T15-47-31.151Z`。

保留 DSH，Provider/model 为 `.env` 中的 `deepseek-official / deepseek-flash`，没有调整 effort、输出 token 上限或用户的 DSH Web 配置。本仓库 Hooks 始终为空，未恢复自动采集、自动召回或后台生产队列。

## 实现

- 提炼：`packages/memo/src/agents/material.ts` 生成模型视图。用户/助手原文保留，长工具结果展示元数据和首尾片段，单条 1,200 字符、每批工具正文 8,000 字符；消息 ID、角色和来源时间保留，省略有明确标记。传输日志路径、字节游标不再进入模型。完整来源仍由现有存储保存。
- 比较：只传新事实/修订引用的证据消息，保留范围、有效期、来源时间和资格等必要字段。新事实正文只有一份。每次向量查询仍取 top 5，但相似度至少 0.5，合并最多 24 条；模型侧旧事实预算 24,000 字节，选择整条事实，不裁切语义。发布事务仍按原始来源校验关系、范围与连续原文引文。
- 缓存和观测：固定系统提示、确定的字段顺序、动态 ID 后置，旧候选在选定后稳定排序。每次输出保存实际 usage 和原始/模型材料字节数；修复尝试也单独留存，缺少 usage 保持不可用，不补成零。

## 手动用例

复用原有隔离 PostgreSQL 验证入口，真实调用 DSH SDK 和 Qwen Embedding，并沿 `processJob` 完成提炼、向量召回、关系比较、入库。只处理脚本创建的两个测试批次，不运行生产 worker，不读取或清空生产队列。旧事实在临时数据库中显式构造，测试数据库运行后销毁，DSH 会话记录与本地报告保留。

两个用例各带约 132 KB 原材料，主要为合成的重复测试日志；没有为了提高缓存命中率额外预热或重复发送相同请求。

| 用例 | 验证结果 | DSH 调用 | 输入 token | 命中 token | 命中率 |
|---|---|---:|---:|---:|---:|
| 明确把生产地址由 old 改为 new，旧地址作废 | correction；旧事实 superseded；原始长日志保存不变 | 2 | 6,349 | 1,792 | 28.22% |
| 陈述超时为 60 秒，数据库原有 30 秒，没有明确更正 | conflict；旧事实 conflicted；没有错误覆盖旧值 | 2 | 6,191 | 4,224 | 68.23% |
| 合计 | 两例通过，无格式修复和条目拒收 | 4 | 12,540 | 6,016 | **47.97%** |

四次调用总输出为 3,752 token。DSH 的 `inputTokens` 是未缓存输入；这里输入总数包含 cacheRead/cacheWrite，避免把命中部分漏出分母。表中命中率是汇总 token 后计算，不是两条百分比取平均。

| 请求 | 原始材料字节 | 模型材料字节 | 输入 token | 命中 token |
|---|---:|---:|---:|---:|
| 用例 1 提炼 | 132,564 | 3,909 | 4,002 | 1,024 |
| 用例 1 比较 | 136,241 | 2,558 | 2,347 | 768 |
| 用例 2 提炼 | 132,473 | 3,818 | 3,984 | 2,816 |
| 用例 2 比较 | 135,318 | 1,909 | 2,207 | 1,408 |

四次请求的材料总量由 536,596 字节变为 12,194 字节，减少 97.73%。这个比例只衡量两个合成用例的 user JSON，不包含 system prompt，也不是生产流量节省比例。系统提示分别为提炼 10,939 字节、比较 6,327 字节。

之前历史请求的命中率为 13.3%，本次为 47.97%，但两组任务内容、时间和缓存状态不同，不能当成严格 A/B 增幅或长期承诺。第二例命中率较高说明固定前缀有实际复用，不能据此推断任意后续请求都会达到同样水平。
