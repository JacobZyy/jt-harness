# 记忆 Agent 质量评测

这套评测直接调用现有 `extractMemories()`，保持 Agent 的提示词、代码、模型配置和插件配置不变。它检验当前提炼阶段，不涉及 CLI、Embedding、记忆库合并或检索。

## 样本与方法

`cases.ts` 固定了 30 个新构造的中文与混合语言场景、68 条预期，其中 34 条标记为严重错误条件。它们依据当前需求编写，属于合成场景，不是从生产会话随机抽样，也不是外部人员标注的数据集。

正常场景执行一次。明确确认、未确认、未决冲突、业务与界面状态、提示注入、长噪声这 6 个场景分别执行 3 次，共 42 次真实提炼。每次启动独立 DSH Session，不缓存提炼结果。最长样本 122 条消息，约 24 KB；不代表已经验证超长对话极限。

候选模型读取 `../runtime.json`，独立评审模型固定为同一 DSH provider 下的 `glm-5.3-flash`。评审前运行三个校准用例：已知正确结果、缺失关键事实、伪造用户确认。校准失败即停止，不将校准结果计入候选得分。

评审逐条判断预期是否满足，以及每条候选知识的内容、依据类别、适用范围和修订是否有来源支撑。评分解析器要求覆盖所有预期和全部输出记录，拒绝漏评、重复计分和虚构路径。独立模型评分仍可能误判，报告需要检查失败实例，并区分自动评分与后续 AI 复核；没有人工标注时不得声称经过人工验收。

## 执行

在 `jt-harness` 根目录执行：

```sh
pnpm typecheck
pnpm test
pnpm memo:eval
```

本次机器的继承代理路径无法正常访问模型服务，TokenHub 直连探测成功。因此实际评测仅为当前命令添加了 `NO_PROXY` 例外，没有修改系统代理或用户的 DSH 配置：

```sh
NO_PROXY="$NO_PROXY,tokenhub.zhuanspirit.com" \
no_proxy="$NO_PROXY,tokenhub.zhuanspirit.com" \
pnpm memo:eval
```

运行目录是 `artifacts/memory-agent/evaluation/<时间戳>/`，包括：

- `manifest.json`：模型、并发数、计划运行次数及候选代码和评测定义的 SHA-256。
- `cases.json`：本轮输入与预期快照。
- `calibration-*.json`：评审模型的校准输入与输出。
- `Cxx-n.json`：逐次提炼结果、DSH Session ID、耗时及评分理由。
- `results.json`：全部结果汇总，包含提炼失败和评审失败。
- `completed.json`：结束时间及冻结文件未变的确认。

单次失败不会被隐藏或替换为成功输出；缺少凭据或认证失效会停止运行。提炼失败和评审失败分开记录，不能把评审服务失败算成 Agent 的语义失败。未给出模型服务单价时只报告 Token 用量，不估算账单。

本轮使用已有 Node.js、DSH SDK 和 Zod 批跑，无新增依赖。原计划参考 Promptfoo 接入，但 npm registry 请求出现 `ECONNRESET`，因此没有安装或声称使用 Promptfoo。后续接入 Promptfoo 时可以复用这里的输入、预期和候选调用函数。

## 指标口径

- 执行成功率：返回有效结构化结果的次数 / 实际提炼次数。
- 严格语义通过率：全部预期通过且每条输出有依据的次数 / 成功完成评审的次数。
- 严重错误：带 `critical` 的预期不通过，单独列出，不能被其他项目的高分抵消。
- 分维度预期通过率：该维度通过的预期数 / 该维度已评分的预期数。
- 输出依据支持率：评审认为有依据的输出记录数 / 全部已评审记录数。它是模型判定的指标，不等同于经人工标注的精确率。
- 重复运行稳定性：同一场景三次全部通过，或出现通过/失败翻转；模型输出和评审模型两者都可能造成波动，必须结合原文复核。

修改提示词前先保存本轮基线。后续修复使用新的运行目录，保留失败记录，另加未参与修复的新验收样本。
