# 任务验收约定

本约定由主 Agent 在任务收口时执行，也可由其他上层流程直接引用。它核对任务是否交付；机器检查由项目现有工具执行。无需另开审查 Agent、调用提炼模型或创建验收数据库。

## 条件来源

通用底线随 Flow 安装，在所有项目中保留：

- 用户要求的必需产物和行为已经实现，没有遗漏任务项。
- 改动和读取服务于授权目标，没有把局部需求扩大成无关审查或重构。
- 本次实际适用的项目约定与 Skill 要求得到落实；以产物、改动或执行结果判断，读过 Skill 不等于执行过。
- 完成结论有对应证据；未执行、失败或无法确认的内容不得标为通过。

再叠加当前用户的验收要求，以及适用 `AGENTS.md` 中的项目条件或明确链接的验收文档。按任务范围读取，不遍历全部 Skill 或项目文件寻找新要求；遵守现有指令优先级。项目补充不会自动删除通用底线；条件不适用时可略过，必要时说明原因。

项目可在 `AGENTS.md` 添加“Flow acceptance”段落，或链接自己的 Markdown。每条说明**何时适用、要达到什么结果、从哪里取得证据**即可，不需要专用配置格式。只编辑本次获授权的项目条件，不把当前任务约束永久写进项目规则。

例如：修改 CLI 参数时，帮助文本、文档和实际执行一致；证据取对应 `--help`、调用结果及变更文件。命名涉及业务职责时，检查名称能否表达实际责任；大小写和格式沿用已有 lint/formatter。

## 执行节点

1. 开始时把必需交付与适用条件对应到当前原生计划项。使用宿主 ID；没有逐项 ID 时保留计划中的 T1 等稳定标签。工具不可用时沿用会话中明确的任务项，不伪造原生状态。
2. 收口时检查实际产物或差异，逐项核对通用底线和项目条件。只检查与本次任务相关的命名、职责及 Skill 要求，不扩展成全仓库审查。
3. 复用已有机器检查的命令、作用范围、实际结果和产物，确认其覆盖本次交付。检查输入、运行环境或验收条件发生影响结果的变化，就补跑受影响的检查；无关变化不要求重跑全部测试。提交成功、Hook 被触发或命令退出 0，均不能代替预期业务结果。
4. 把结果及最小证据绑定到对应任务项，保留在原生计划或会话；只有跨会话确需引用时才另存小份报告。主 Agent 负责核对，包括子 Agent 返回的结论。
5. 必需条件全部满足才完成验收项、结束计划和 Goal。否则回到相关任务项修复，或报告具体阻塞与未完成条件；暂停、blocked 等状态仍按宿主规则处理。

尚未运行的 Stop Hook 不能作为本次结束前的通过证据。需要先拿到结果才能完成的检查，应提前运行已有命令或等待已经启动的检查；后置 Hook 仍负责其原有工作。测试通过也不能证明需求范围、语义命名或 Skill 执行程度已达标。

输出只保留“对应任务、是否通过、证据、未完成项”。证据可以是检查结果、文件位置或实际行为；不用统一 JSON、全量日志或重复贴完整任务列表。没有必需未完成项时无需输出空表。
